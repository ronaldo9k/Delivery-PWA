2. 자동은 언제 시작되나요? (방아쇠 3개)
① 1분 타이머 A — 「택배발송」 체크를 대신 켜주는 일꾼
함수 syncShippingFlagFromDeliveryType
조건 : 납품형태 = 「택배 발송」 또는 「택배 제2배송처」 이고 택배발송 체크가 꺼져 있고 Slack전송완료가 비어 있는 페이지.
하는 일 : 그 페이지의 택배발송 체크박스를 자동으로 켭니다. (사람이 손으로 체크 안 해도 됨)
이미 도장이 찍힌 옛날 페이지는 절대 다시 켜지 않습니다. 그래서 옛날 190건이 갑자기 알림으로 몰려오지 않아요.
② 1분 타이머 B — 진짜 알림을 쏘는 일꾼 (심장)
함수 processShippingNotifications
조건 : 택배발송 체크가 켜진 페이지를 노션에서 찾아옵니다.
하는 일 : 한 건씩 Slack 전송 → 성공하면 노션에 도장 → 이력 시트에 기록.
안전장치 : 한 번에 최대 20건, 노션 호출 사이 0.35초 쉼, 동시 실행 금지(LockService).
③ 사람 손 — 웹앱 새로고침
택배 카드에서 🔄 새로고침을 누르면 doGet → getRecentShippingCards_ 가 실행되어 이력 시트를 읽어 카드로 보여줍니다.
이때 PWA 접속 토큰(PWA_ACCESS_TOKEN)이 맞아야만 데이터를 줍니다. 틀리면 “접근 권한이 없습니다.”
3. 알림 1건이 처리되는 순서 (①~⑨)
  1. 노션에서 새 주문 페이지에 납품형태를 「택배 발송」으로 입력.
  2. 타이머 A가 1분 안에 발견 → 택배발송 ✅ 자동 체크.
  3. 타이머 B가 그 페이지를 읽음 → sendOnePage_ 시작.
  4. 입출고 DB에서 연락처 1 / 주소 / 지번주소를 먼저 읽음.
  5. 거래처(Relation) 페이지를 한 번 더 열어 거래처명·연락처·도로명·지번을 보완.
  6. 「제2배송지」 Select에 값이 있으면 제2배송처 관리 DB에서 연락처·주소를 찾아옴. (★이번에 고친 부분)
  7. buildSlackMessage_가 메시지를 만들고 Slack으로 전송.
  8. 성공하면 노션에 Slack전송완료 = 「전송완료」 도장 + 택배발송 체크 해제 (updatePageFlags_).
  9. 이력 시트에 19칸 한 줄 저장 (appendHistory_). → 택배 카드에 등장.
만약 7번에서 Slack 전송이 실패하면? 도장을 찍지 않습니다 → 다음 1분에 다시 시도합니다. 이력에는 ❌ 실패로 남습니다.

6. 택배 카드에 카드가 뜨는 조건 (3개를 모두 만족)
  1. 이력 시트의 전송결과가 「✅ 전송완료」 인 줄
  2. 납품형태가 「택배 발송」 또는 「택배 제2배송처」
  3. 납품요청일이 어제·오늘·내일 중 하나이고, 그 페이지에 납품일자가 비어 있음
GAS와 웹앱이 똑같은 조건을 두 번 검사합니다(이중 안전장치). 그래서 GAS가 실수해도 폰 화면에 옛날 건이 몰려오지 않아요.
7. ★ 제2배송지 — 이번에 고친 부분
원래 내가 원한 그림 (3단계)
  1. 1단계 · 입출고 DB의 「제2배송지」(Select) 에서 이름 하나를 읽는다. 예: “대한물류”
  2. 2단계 · 그 이름으로 제2배송처 관리 DB를 뒤져 연락처·상세주소를 찾는다.
  3. 3단계 · 카드 맨 위 금색 박스에 납품처 · 연락처 · 주소 3개를 보여준다.
그런데 실제로는? (고장 난 이유)
2단계에서 엉뚱한 곳을 뒤졌습니다. 코드가 구글시트의 「AddressBook」이라는 시트를 찾아갔는데, 이 스프레드시트에는 그 시트가 없습니다. (AddressBook은 발주서 웹앱 쪽 다른 GAS의 시트)
그래서 1단계 이름은 노션에서 잘 나왔지만(= 금색 박스의 “납품처”는 보임), 2단계에서 아무것도 못 찾아 연락처·주소가 빈 값 → 화면에 “-” 로만 표시된 것입니다.
어떻게 고쳤나?
  • 이제 노션 「제2배송처 관리 DB」를 1순위로 읽습니다. (실제 데이터가 있는 곳)
  • DB를 찾는 방법은 2가지 → ① 스크립트 속성 SECOND_DEST_DATABASE_ID 에 주소를 넣으면 그 DB, ② 안 넣으면 이름에 “제2배송처”가 든 DB를 자동으로 찾아냄.
  • 속성 이름이 “거래처명”이 아니라 “거래처/상호/업체명”이어도, “연락처”가 “전화번호/휴대폰”이어도 찾도록 후보 이름을 여러 개 준비했습니다.
  • 구글시트 AddressBook은 “혹시 있을 때만” 쓰는 2순위 보조로 남겨뒀습니다. (있으면 좋고, 없어도 됨)
  • 그래도 못 찾으면 카드에 “주소 미등록” 배지가 뜹니다. (거짓으로 채우지 않음)
확인 방법 : GAS 편집기에서 testSecondDestLookup 함수를 ▶ 실행 → 로그에 DB ID · 읽어온 건수 · 매칭 결과가 그대로 나옵니다.
8. 왜 알람이 무한 반복되지 않나요?
비밀은 도장입니다. Slack 전송에 성공한 순간에만 노션의 Slack전송완료 = 「전송완료」 를 찍습니다. 타이머 B는 도장이 있는 페이지를 무조건 건너뜁니다.
전송이 실패하면 도장을 안 찍습니다 → 1분 뒤 다시 시도 → 성공하면 그때 도장. 이게 정상 동작입니다.
예전 버전이 무한 반복이었던 이유 : 「Slack전송완료」를 체크박스로 착각해서 도장이 안 찍혔기 때문. 지금은 Select 방식으로 바뀌어 정상입니다.

10. 뭔가 이상할 때 확인 순서
  1. Slack 알림이 안 와요 → 노션에서 ① 납품형태가 정확히 「택배 발송」인지 ② 택배발송 ✅ 가 켜졌는지 ③ Slack전송완료에 도장이 남아있지 않은지 확인.
  2. 카드가 안 보여요 → 납품요청일이 어제~내일인지, 납품일자가 채워져 있지는 않은지 확인. (납품일자를 비우면 다시 나타남)
  3. 연락처·주소가 “-” → testSecondDestLookup 실행. 로그에 “찾지 못함”이 뜨면 ① GAS 통합에 그 DB를 연결(공유)했는지 ② 그 업체 이름이 DB의 거래처명과 똑같이 적혀 있는지 확인.
  4. 토큰 오류 → GAS에서 setupPwaToken 실행해 나온 값을 웹앱에 다시 입력.
  5. 웹앱이 연결 실패 → GAS_API_URL 이 현재 배포된 웹앱 주소인지 확인 (재배포하면 주소가 바뀔 수 있음).
